# AI로 예측하기 (시험) — 기획 (보류)

> 2026-10 보류. 지수 데이터는 줄 수(약 3만)는 충분하지만 2003년 이후 큰 흐름이 4번 정도뿐이고 지역끼리 같이 움직여서, 시기 예측은 장기 평균을 이기기 어렵다고 판단. 다시 한다면 맞힐 값을 '시도 대비 초과 상승률'로 바꾸고, 실거래 원본은 레포가 아니라 Releases·R2에 달별 parquet로 쌓기.

## 목표
지금 계산기의 집값 상승률 기본값은 "2003년부터 장기 평균" 하나뿐이다.
AI 탭은 **지역의 최근 흐름까지 반영한 상승률 예측을 범위로** 보여주고, 그 범위로 매매·전세·월세를 다시 계산해준다.
숫자 하나를 맞히는 게 목적이 아니라, "가운데로 보면 매매, 낮게 보면 전세"처럼 **결론이 얼마나 단단한지**를 보여주는 게 목적.

## 범위 (첫 버전)
- 아파트만. 빌라·오피스텔은 지수가 시도 단위라 제외(탭은 "아파트에서만 볼 수 있어요" 안내)
- 매매가격 상승률만 예측. 전세 상승률·금리는 지금처럼 기본값 유지
- 매매·전세·월세마다 모델을 따로 만들지 않음. 계산기에서 결과를 가르는 미래 값은 집값 상승률(매매)과 전세 상승률 두 개뿐이고, 월세는 전세금 × 전환율로 따라 움직임
  - 1단계: 매매 상승률 모델 하나
  - 2단계(선택): 같은 변수로 맞힐 값만 전세지수 상승률로 바꾼 모델 하나 추가 → 전세·월세 쪽에 반영
  - 월세 따로는 안 함 (부동산원 월세지수는 2015년부터라 학습 기간이 짧음)
- 예측 기간: 1년·3년·5년. 6년 이상은 5년 예측에서 장기 평균으로 점점 섞음
  - N년 상승률 = (5 × 5년 예측 + (N−5) × 장기 평균) ÷ N

## 화면 (결과 칸 세 번째 탭: "AI로 예측하기 (시험)")
```
AI는 노원구 아파트값이 앞으로 5년 동안
해마다 +1.6% 오를 걸로 봐요 (낮게 −0.5% ~ 높게 +3.8%)
84㎡(34평형) 8억 2,700만 원 → 5년 뒤 약 9억 (8억 1천만 ~ 9억 9천만)

  높게 보면   매매가 전세보다 1억 2천만 원 더 이득
  가운데로    매매가 전세보다 3,100만 원 더 이득
  낮게 보면   전세가 매매보다 1,800만 원 더 이득

왜 이렇게 봤나요?                         (EBM 기여도 상위 5개)
  최근 3년 상승률이 낮음        −0.6%p  ■■■
  전세가율이 높음               +0.4%p  ■■
  주담대 금리가 내려가는 중      +0.3%p  ■■
  ...
[이 예측으로 계산하기]  → 직접 조정의 상승률을 가운데 값으로 바꿈

시험 기능이에요. 2003년~2026년 부동산원 지수로 학습했고,
과거에 이 방식으로 5년을 예측했을 때 평균 오차는 ±1.2%p였어요 (장기 평균 방식은 ±1.5%p).
```
- 범위는 가능성 80% 구간
- 기간(N년)을 바꾸면 1·3·5년 예측 중 맞는 것(+ 섞기)으로 바뀜
- FAQ에 모델·데이터·검증 방법 질문 추가

## 모델
- **EBM** (`interpret` 패키지 ExplainableBoostingRegressor). 기여도를 그대로 화면에 쓸 수 있어서 선택
- 전국 시군구를 한 모델로 학습 (지역별 따로 하면 데이터가 너무 적음). 기간(1·3·5년)마다 모델 하나씩

### 학습 데이터 (지역 × 달 = 한 줄)
- 출처: 부동산원 월간 아파트 매매·전세가격지수(2003.11~), 한국은행 주담대 금리(과거값 같이 수집)
- 맞힐 값: 그 달부터 h년 뒤까지 매매지수 연평균 상승률(%)
- 변수
  - 지난 1·3·5·10년 매매 상승률, 최근 6개월 기울기, 2003년 이후 최고점 대비 하락폭
  - 전세가율 흐름(전세지수/매매지수의 지난 3년 변화), 지난 3년 전세 상승률
  - 주담대 금리 수준과 지난 1년 변화
  - 시도(범주), 서울·수도권 여부
  - 거래 쪽 (실거래가·거래량): 매매 거래량의 지난 1년 변화(가격보다 먼저 움직이는 편), 그 지역 평당가가 시도 안에서 몇 번째인지(가격 수준), 실거래 중간값과 지수 흐름의 차이
    - 거래량은 부동산원 R-ONE의 월별 아파트 매매 거래현황(시군구)을 같이 받음. 국토부 API로 과거 23년치를 다시 받으면 하루 호출 한도를 훨씬 넘음

### 왜 가격이 아니라 상승률을 맞히나
- 지역마다 가격 수준이 수십 배 달라서, 가격을 바로 맞히게 하면 모델이 "강남은 비싸다"만 배움. 상승률은 지역끼리 비교가 돼서 전국을 한 모델로 학습할 수 있음
- 계산기도 "지금 가격 × (1 + 상승률)^기간"으로 계산하므로 상승률이 바로 쓰임
- 화면에는 가격으로 바꿔서도 보여줌: "84㎡(34평형) 8억 2,700만 원 → 5년 뒤 약 9억 (8억 1천만 ~ 9억 9천만)"
- 같은 지역의 이웃한 달은 거의 같은 데이터 → 검증은 반드시 시간 순서로

### 범위 (예측 구간)
- EBM 가운데 예측 ± 검증 구간 오차 분포의 10%·90% 지점 (split conformal)
- 기간·시도별로 오차를 따로 모아 지역마다 범위 폭이 다르게

## 백테스트 / 공개 기준
- 걷기 검증: 2012·2014·…·2021년 각각까지만 학습 → 그 뒤 h년 실제와 비교
- 비교 대상: ① 2003년부터 장기 평균(지금 기본값) ② 지난 10년 평균
- **공개 조건**: 3년·5년 모두 평균 오차가 ①보다 작고, 80% 범위 안에 실제가 들어간 비율이 70~90%
- 조건을 못 넘으면 탭을 열지 않고 README 향후 일정에 결과만 기록

## 계산기 연결
- `engine.js`는 그대로. 탭에서 상승률만 p10·p50·p90으로 바꿔 `simulate`를 세 번 호출
- "이 예측으로 계산하기"는 직접 조정의 상승률을 p50으로 바꾸고 결과 탭으로 이동 (기존 "기본값으로 되돌리기"로 원복)
- `forecast.json`이 없거나 그 지역 예측이 없으면 탭을 숨김

## 순서
1. `forecast.py` 학습·백테스트만 → 결과 표 확인 (공개 조건 판단)
2. 통과하면 JSON 출력 + 화면 탭 + FAQ
3. 매달 자동 갱신에 연결
